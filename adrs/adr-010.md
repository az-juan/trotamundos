## ADR-010: Analítica — ClickHouse con Batch Ingest

**Status**: Aceptado
**Fecha**: 2026-10-26
**Decidido por**: Equipo de arquitectura

### Contexto

El equipo de datos necesita ejecutar consultas analíticas pesadas (tendencias de destino, cancelaciones por aerolínea, cohortes de usuarios) sin impactar el SLA de 800 ms del panel. Se requiere retención de 2 años y consultas de 5–30 s.

### Decisión

- **ClickHouse** self-hosted (segundo Droplet, 16 GB RAM / 8 vCPU, $96/mes en Fase 1).
- **Ingesta**: consumo de NATS → buffer en memoria → **batch insert** (5000 rows o 5 s, whichever first).
- **Schema**: `MergeTree` (eventos crudos) + `AggregatingMergeTree` (materialized views para pre-agregados).
- **Particionamiento**: `PARTITION BY toYYYYMM(event_date)`. TTL: 2 años.
- **Query API**: `clickhouse-go/v2` con `context.WithTimeout(30s)`.
- **Dashboard**: Metabase (self-hosted) para el equipo de datos. No expuesto al usuario final.

### Consecuencias

| Positivas | Negativas / Riesgos |
|-----------|-------------------|
| Consultas analíticas (30 s) no impactan el OLTP (PostgreSQL) | Un sistema más a operar (mitigado: ClickHouse es "set and forget" una vez configurado) |
| Batch insert: 10× más rápido que fila por fila | No soporta UPDATE/DELETE eficiente (no se necesita: append-only + `ReplacingMergeTree` para estado) |
| Materialized views: agregaciones en tiempo de inserción, no de consulta |  |
| Particionamiento por mes: drop de datos viejos = O(1) | |
