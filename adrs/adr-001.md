## ADR-001: División en microservicios + Web + Gateway

**Status**: Aceptado
**Fecha**: 2026-10-26
**Decidido por**: Equipo de arquitectura

### Contexto

El sistema debe soportar 15 M de cuentas, 2 M de usuarios activos/semana, y picos disruptivos (tormentas, cancelaciones masivas). La división debe permitir escalado independiente de los perfiles de carga opuestos (batch CPU del escáner vs. per-request del panel).

### Decisión

**Fase 0: 4 servicios de dominio + Web BFF + Mobile BFF + Gateway = 7 deployables**

| Servicio | Bounded Context | Perfil de carga |
|----------|----------------|----------------|
| **Itinerary** | Viaje, Reserva, Viajero, Ciclo de Vida | Per-request, latencia baja (800 ms) |
| **Email Ingest** | Escaneo, Parsing, Whitelist | Batch + CPU, bursty |
| **Integration** | Contratos con proveedores, Mapeo, Webhooks | Per-request, I/O-bound (llamadas externas) |
| **Analytics** | Tendencias, Destinos, Estadísticas | Batch, OLAP, no per-request |

**No son servicios en Fase 0**: Auth (middleware del Gateway), Notificaciones (módulo de Itinerary), User/Perfil (tabla en PG + módulo de Itinerary).

**BFF por experiencia (ADR-013)**: Web BFF (templ+htmx, HTML) y Mobile BFF (chi, JSON) son deployables propios, uno por experiencia; todo el tráfico de clientes entra por el Gateway. **Auth/JWT (ADR-014)**: en Fase 0 el Gateway emite y valida JWT RS256 (JWKS propio); en Fase 2 se extrae Identity como IdP OIDC.

**Fase 1**: se extrae **Notification** (burst opuesto al de Itinerary).
**Fase 2**: se extrae **Identity** (OAuth, tokens, social).

### Regla de decisión para extracción futura

Separar un módulo en servicio propio solo si se cumplen **2 de 3**:
1. Perfil de escalado medible que difiere.
2. Ciclo de deploy independiente (cambia con frecuencia distinta).
3. Un fallo no debería tumbar el resto.

### Consecuencias

| Positivas | Negativas / Riesgos |
|-----------|-------------------|
| Escalado independiente: Email Ingest a 10 réplicas sin tocar Itinerary | 7 deployables = 7 pipelines de CI/CD (mitigado: template de GitHub Actions) |
| Aislamiento de fallos: Gmail caído ≠ panel caído | Comunicación entre servicios = red (mitigado: NATS en misma red Docker) |
| Cada servicio tiene su propio `go.mod`: builds independientes | Overhead de red entre servicios (mitigado: misma red, < 1 ms) |
| Trazabilidad: cada servicio = 1 ADR de arquitectura + 1 ADR por puerto | |
